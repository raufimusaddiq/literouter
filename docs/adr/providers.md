# Providers and OAuth

Upstream quirks that look wrong but are required. Most were found from live failures. Executors under `open-sse/executors/`, registry under `open-sse/providers/registry/`.

## OpenAI-compatible and gateway quirks

- **Kenari `/v1/models` answers 200 for any key**, so validate via `/v2/quotas` (401 "invalid key"). `/v1/responses` honors only flat function tools, rejects `text.format` and `role:"system"` (`responsesSystemRoleUnsupported`: fold into the first user turn), and 400s on lone surrogates, so serialize with `stringifyWellFormed`. Where: `src/app/api/providers/[id]/test/testUtils.js`, `open-sse/utils/wellFormedJson.js`.
- **Alibaba and SenseNova key types are per host, so each is its own provider**: `alicode-intl` (`sk-sp-`, coding-intl host, #2591), `alims-intl` (`sk-`, dashscope-intl), `alitp-intl` (Token Plan, Singapore only, OpenAI mode only); `preserveCacheControl` keeps DashScope `cache_control` (#2069); SenseNova intl keys are rejected by `token.sensenova.cn`. Where: registry `alicode*.js`, `sensenova*.js`.
- **DeepSeek**: the Anthropic endpoint accepts only `web_search_*` tools (`claudeSupportedToolTypes`); the catalog id `deepseek-v4.1-flash` must leave as the upstream name via `upstreamModelId` (`deepseek-flash`; #4940). Where: `registry/deepseek.js`.
- **`stream_options` is deleted from non-streaming requests** (NVIDIA NIM, DeepSeek 400; also Fusion panels, #3024); `dropClientMetadata` quirk removes Anthropic's `client_metadata`. Where: `open-sse/executors/default.js` `transformRequest`.
- **Cline** wraps non-stream bodies in `{"success":true,"data":{...}}`: unwrap only for providers with `quirks.clineEnvelope`. Cline OAuth tokens get the `workos:` prefix; ClinePass `clp_...` keys are sent verbatim (401 otherwise, #2333).
- **Kimi** is dual-auth (device-code OAuth and API key) sharing one transport; keep one stable `deviceId` per connection (`X-Msh-Device-Id`), refresh threshold 300s; API-key connections also need `usageApikey`. K3 ids: `kimi-k3` (platform), `k3` (Kimi Code OAuth).
- **Kimchi** counts echoed reasoning as input; strip only real `reasoning_content`, keep placeholders (<= 8 chars).
- **Trae SOLO** is a two-step agent flow: POST `{base}/chat_sessions`, then GET `.../events?reply_to_message_id=` as SSE (`plan_item` thought is cumulative, `token_usage`, `done`, `error`); auth `Authorization: Cloud-IDE-JWT <jwt>` (RS256, ~14 days); query is a JSON string of typed blocks.
- **System One** forwards only allowed client headers; custom `systemone-<uuid>` nodes resolve asynchronously; Cloudflare Workers AI wraps responses in `{ result, success }`.
- **Xiaomi MiMo free chat needs a Chrome User-Agent and a system message containing the MiMoCode signature** (`MIMO_SYSTEM_MARKER`) or 403 "Illegal access" (#1933). Preview models are resolved in `buildUrl` before `runtimeTransport` (account route is OpenAI format only); the session cookie is resolved in async `execute()` and read in sync `buildHeaders()`; defaults never override caller params; the Desktop `passToken` is persisted per connection (null while Desktop runs). API-key import soft-fails (stored untested). Where: `open-sse/executors/xiaomi-mimo.js`.
- **GitHub Copilot**: Claude models go to Anthropic-native `/v1/messages` (only endpoint exposing cache token counts), chosen by name pattern at request time, not registry `targetFormat` (live catalog lists new `claude-*` first; a static field double-translates). The executor translates OpenAI to Anthropic itself, forces `stream:true`, and must strip `_toolNameMap` (strict schema 400). Never escalate Gemini or Claude to `/responses` (#1062). `/chat/completions` accepts only `text`/`image_url` parts and `max_completion_tokens` for gpt-5+/o1/o3/o4; reasoning "none" is stripped. Where: `open-sse/executors/github.js`.
- **Zed**: `ZedExecutor` overrides `execute()` (thread envelope, short-lived bearer from the RSA-decrypted token, NDJSON `{"event":...}` lines); the `provider` field takes exact catalog spellings (`anthropic`, `open_ai`, `google`, `x_ai`; else 500); auth is `Authorization: <user_id> <access_token>` plus `x-zed-cloud-token`; drop client `safetySettings` on the Google path (Vertex vocabulary); registry catalog is empty with passthrough and resolved live per connection with a warning on empty/failure. Where: `open-sse/executors/zed.js`, `open-sse/shared/zedAuth.js`.
- **Grok CLI** (`cli-chat-proxy.grok.com`, Responses API): `GROK_CLI_VERSION` must be a current `@xai-official/grok` release (426 below the floor; min 1.0.13); keep `role:"system"` (do not convert to developer); effort priority explicit > `reasoning_effort` > model suffix > `high`, omitted for grok-build/Composer; per-request ids ride the transformed body (singleton executor); connection test probes `/v1/user` and treats a 402 spending-limit as soft success. Where: `open-sse/executors/grok-cli.js`.
- **CommandCode** `/alpha/generate`: `params.system` is a top-level string, `messages[].role` user|assistant|tool, `content` always an array of blocks, images as `{type:"image", image:"data:...", mimeType}`, tool-call/tool-result blocks, Anthropic-plain tools; auth `Bearer user_xxx` plus per-request `x-session-id`. Response is AI SDK v5 NDJSON (no `data:` prefix) translated in the executor; emit the consolidated `tool-call` only when no `tool-input-*` deltas were seen; a mid-stream error throws. Where: `open-sse/executors/commandcode.js`.
- **Windsurf stays hidden until it supports tool calls** (ToolCallChunk is skipped). gRPC-web `GetChatMessage`, Codeium apiKey in `Metadata.api_key` and Bearer; four auth paths all end in an apiKey. Where: registry, `open-sse/executors/windsurf.js`.
- **OpenCode Zen free lane / OpenCode Go**: free-tier requests must carry the lowercase quartet `bash`, `glob`, `grep`, `read` exactly once (rename `Read` to `read`; 403 FreeTierError otherwise); response side restores the caller's spelling, including openai-to-openai passthrough (#4986, #4994), via a request-local WeakMap. Always stream upstream. Retry only "overloaded" 429s (8 attempts, 800 ms base, 4000 ms cap, ~20 s); the free-quota 429 also says "try again later" and is not transient. One stable `x-opencode-session` per downstream identity (a fresh one per request burns quota), request id derived from session plus last user message; drop a rejected session on non-transient failure (#5559); never replace a client-supplied one. `reasoning_effort` only the plain enum (omit `auto`); Responses demotes named/required/none to `auto` only for `forceAutoToolChoiceModels`; `oc/deepseek-v4.1-flash-free` serves exactly low|high|max; MiMo free lane streams `reasoning`/`reasoning_details[]`. Zen reasoning models 400 on assistant history without `reasoning_content` (inject placeholder). Luna is Responses-only (pin target format and transport); a model whose Responses endpoint 500s routes through Chat. Where: `open-sse/executors/opencode.js`, `opencode-go.js`.

## Chinese-gateway and CLI-impersonating providers

- **CodeBuddy (CN `copilot.tencent.com`, intl `codebuddy.ai`)**: force `stream:true` (non-stream 400 code 11101); send the official plugin's conversation/request ids or 400 `11128` "request illegal" channel check; neutralize CLI-agent system prompts (content filter/WAF, intl may ban) while keeping legitimate operator prompts, markers are CLI identities only (CN length catch-all plus regex; intl replaces only marker lines); intl needs a leading system prompt and typed content blocks; reasoning is opt-in (`reasoning_effort` plus `reasoning_summary:"auto"` only when requested; forcing both trips the filter, #2071); thinking format forced to openai; catalog mirrors the server's list (removed models kept removed; `-x` is the paid tier; CN prefix `cbcn`, `cbai` reserved); refresh is `POST /v2/plugin/auth/token/refresh` with `X-Refresh-Token` header, response `{code:0,data}`; intl uses `/v2/plugin` and `platform=ide` (CN `platform=CLI`). Where: `open-sse/executors/codebuddy-*.js`.
- **Qoder** (`qodercli` impersonation, COSY-signed): per-model `model_config` must be the server-published one (wrong one silently downgrades; missing is a hard error); token kinds `dt-` (api3), `jt-` (must use api2, api3 403 "Login expired"), `pt-` (exchange for a job token; keep it in `apiKey`, and the `/v1/models` resolver must pass it on); device tokens cannot refresh (upstream 403), so surface 401 and ask re-login; body is `QoderEncodeBody` (base64, thirds reordered, custom alphabet, `&Encode=1`) before signing; COSY = AES-128-CBC payload, RSA-wrapped key (first 16 chars of a fresh UUID, hyphens included), MD5 over `payload || cosyKey || timestamp || body || sigPath`, ~17 `Cosy-*`/`X-*` headers cased like qodercli (`Cosy-Machineid`); force `Accept-Encoding: identity` (gzip trips CDN signature validation); never replay a signed request directly (403 code 103), retry through `execute()`; auto-escalate context tier from estimated prompt size (CJK ~1 token/char, else 4 chars/token; `QODER_CONTEXT_TIER`); upload attachments (COSY multipart PUT to `/algo/api/v2/image/upload`), do not inline data URIs (413); hoist system messages; unwrap `{statusCodeValue, body}` SSE, peek the first frame for errors, map billing codes 110/112/10605/`pricingUrl` to 403, cancel the reader on terminal frames (socket stays open), use `start()` not `pull`; coalesce finish+usage frames. Where: `open-sse/executors/qoder.js`, `open-sse/shared/qoder/*`.
- **Cursor** (AgentService, `agent.api5.cursor.sh`, HTTP/2 + protobuf): route text/tool turns to AgentService, images to legacy; "Auto"/"default" is not a model id (resolve to the account's default agent model); h2 only (use `node:http2`, unary catalog calls unframed `application/proto`, no compressed requests); never set `custom_system_prompt` (empty turn; fold into the user message); `UserMessageAction` needs `selected_context` (3) and `mode=1` (4); ModelDetails (3) required for thinking variants; do not echo tools on the request-context ack (silent stall); reject builtin exec probes, empty-success Diagnostics, and echo KvServerMessage metadata (field 4) verbatim; Composer puts the answer after `</think>` in `thinking_delta` (4); keep `msg_` ids for Claude SSE; messages arrive pre-translated, so `transformRequest` must not call `openaiToCursorRequest` again; tool outputs go as text blocks; `"\nmc_"` delimits `model_call_id` inside `tool_call_id`. Imported IDE tokens are not API-validated. Where: `open-sse/executors/cursor.js`.
- **Kiro** (kiro.dev / CodeWhisperer, EventStream decoded in the executor): host order Amazon surfaces first (q, then codewhisperer), kiro.dev never first (deprecated path gateway 400 `REQUEST_BODY_INVALID`, and 400 is terminal); only allow-listed regions are spliced into hostnames; retry only endpoint/auth-surface failures. API keys: bearer plus `tokentype: API_KEY`; external IdP `TokenType: EXTERNAL_IDP`; IDC tokens must hit `*.amazonaws.com` in their region (profile ARN region normalized to us-east-1); account-bound auth (api key, idc, external_idp) never uses the shared default profile ARN (403 "bearer token invalid"). Never write a top-level `systemPrompt` (400); system text and repair instructions go in the first/current user turn. Validate tool calls per tool, not per turn (one bad fragment used to drop every call); `model_context_window_exceeded`/max_tokens after content is `finish_reason:"length"`, not failure, but `cancelled`/`pause_turn` stay private; count tool-argument bytes as output tokens (402/2156 rows had 0). `KIRO_INTEGRITY_GATE=off` forfeits the repair retry. `-agentic`/`-thinking` suffixes are fictions stripped before sending (`model(level)` consumed first). Per-account fingerprint from a stable credential id; freeze the first user message per session for cacheability. Request translation: `canonicalizeKiroConversation()` enforces adjacent one-to-one tool use/result pairs (the generic helper inserts `role:tool`), flattens structured tool content when `tools` is absent, and returns falsy so chatCore 400s locally (no upstream call, no cooldown); empty user content gets non-instruction placeholder text (a "continue" placeholder was answered literally); merge consecutive user turns keeping `toolResults`/images; sanitize tool names (`mcp__a__b` to `mcp_a_b`) and map back; `kiro-to-claude` consumes OpenAI-shaped chunks (the executor already converted the EventStream). Where: `open-sse/executors/kiro.js`, `open-sse/translator/concerns/kiroConversation.js`.
- **Codex** (`chatgpt.com/backend-api/codex/responses`): its schema validator has no Unicode property escapes, so strip `\p{...}` from tool `pattern` strings on the Codex path only (#3922, #3667; count preceding backslashes, copy-on-write, special-case `properties` keys); send the account header preferring `workspaceId` over `chatgptAccountId` (else cross-binding `token_invalid`); the executor is a singleton, so per-request state lives in a WeakMap keyed by the transformed body; never replay after user-visible output; `refreshLeadMs` is 10 minutes (5 days rotated the token on every call and revoked the session); `-review` variants via `CODEX_REVIEW_SUFFIX`, `codex-auto-review` forwarded verbatim and routed to OAuth Codex (#1398), must not be first in the `cx` list (`getDefaultModel` takes `models[0]`); `CODEX_CLI_VERSION` and `CODEX_CLIENT_VERSION` gate `/codex/models` by `minimal_client_version` (stale returns 200 with entries quietly missing). Where: `open-sse/executors/codex.js`, `open-sse/utils/codexToolSchema.js`.
- **Devin CLI (ACP over stdio)**: inherit the environment so devin uses stored credentials; never inject `WINDSURF_API_KEY` (-32000 "invalid api key"); auto-approve permissions (`DEVIN_PERMISSION_MODE`) or the stream hangs on `session/request_permission`; the agent can run shell commands, so expose it locally only; client tools bridge as a stdio MCP server `clientTools` and only `mcp_`-prefixed names are discovered (add and strip the prefix; ACP `tool_call` is upsert-by-id); extra MCP servers go in a throwaway `XDG_CONFIG_HOME` (ACP mcp/connect is unstable); probe known install dirs before PATH; use the client workspace cwd. ACP 3000.2.x shape: `session/new` needs `mcpServers` array, `session/prompt` needs `prompt` array, notifications nest under `params.update.sessionUpdate`, errors are `errorMessage`. Where: `open-sse/executors/devin-cli.js`.
- **Antigravity** (Google Cloud Code; fingerprints clients, detail-free 429 RESOURCE_EXHAUSTED when it dislikes a request): chat requests must not carry `requestType` (also when leaking through the `...body` spread); rewrite competing-client branding out of system prompts (Zed, OpenCode, Claude Code's identity line); client tools get an `_ide` suffix (`_cc` for Claude) and native decoy tools are injected, names exactly as in the real request log; discovery (`loadCodeAssist`, `onboardUser`) stays on PROD with no `X-Goog-Api-Client`/`Client-Metadata`; thought signatures are per family (a Claude one replayed to Gemini 400s "Corrupted thought signature."), backfilled, only the first parallel call needs one; remove root thinking fields, drop `stream_options` for non-stream, `functionResponse` role user for Claude, merge all declarations into one `functionDeclarations`; session id is stable per connection in memory (mimics per-launch). Where: `open-sse/executors/antigravity.js`.
- **Antigravity strike breaker**: `STRIKE_THRESHOLD` 3 429/409 within `STRIKE_WINDOW_MS` 60s (anchored at the first strike; 409 counts, pool exhaustion) for the same connection+model blocks the pair for `STRIKE_BLOCK_MS` 15 min via a synthesized 0% cache entry (no `modelLock_*` persisted); re-apply active blocks on every fresh snapshot; a success clears strikes and removes only the synthesized entry; an optimistic reading must not poison the shared cache; quota refresh is coalesced and throttled to one per account per 30s, preserving the known cache on 401/403. Where: `src/sse/services/antigravityQuota.js`.

## OAuth

- **Zed login is an RSA keypair, not OAuth**: per-login RSA-2048, private key rides in `codeVerifier`; the token is RSA-OAEP SHA-256 only and fails closed (PKCS#1 v1.5 has no integrity check); the keypair is bound to a port, preferring `defaultNativeAppPort` 58443; the `system_id` in the sign-in URL must be threaded through register-session, exchange and the stored connection (never minted again); no refresh. Where: `open-sse/shared/zedAuth.js`, `src/lib/oauth/providers/zed.js`.
- **Xiaomi MiMo callback is X25519 ECDH**: `?u=` base64 of `[12-byte nonce][32-byte ephemeral pubkey][ciphertext][16-byte GCM tag]`, key = SHA-256 of the shared secret, AES-256-GCM, yielding `{uid, sk, url}`; send the full 44-byte base64 SPKI; `key_name` deterministic per machine. Sessions hold private keys in a Map and must be dropped when the proxy stops; a finished session survives `/poll-status` until `/exchange`. Where: `src/lib/oauth/providers/xiaomi-mimo.js`.
- **Trae** matches the callback by `loginTraceID`, not PKCE state; `ExchangeToken` uses `ClientSecret: "-"`; empty `web_id`/`biz_user_id` are accepted. **Windsurf** is an implicit flow (`?access_token=<firebaseJWT>`) then `RegisterUser`. Where: `src/lib/oauth/providers/trae.js`.
- **Qoder device flow**: `device_code` is the nonce and `codeVerifier` the PKCE verifier; 202/404 mean keep polling; tokens last ~30 days but `center.qoder.sh` refresh 403s, so re-login; `expireTime` is Unix ms, a numeric string is read as ms-epoch, default now + 30 days, `expiresInSeconds === 0` is expired, floor at one day; derive a synthetic email from `userId` when empty (else "Account N" duplicates); helper calls run under an `AbortController`. Where: `src/lib/oauth/services/qoder.js`.
- **Kiro** social login uses the `kiro://` redirect (Cognito whitelists only that), same `redirect_uri` on exchange; IDC/Builder-ID tokens lack `profileArn` (resolve via ListAvailableProfiles; a bearer-only call can return 200 with an empty list for any key); API keys validate through the Amazon Q surface and persist a 365-day horizon (Kiro, MiMo). Where: `src/lib/oauth/services/kiro.js`.
- **Grok CLI** uses plain device_code with no PKCE and surfaces an absolute expiry so proactive refresh renews the ~40-45 min xAI token; 402 spending-limit is a soft success. Kimi returns 200 with an `error` field while pending. CodeBuddy polls with GET and the state query; code 11217 pending, 0 success. Antigravity preserves the registered spelling. Codex needs fixed port 1455 and `/auth/callback`; the `OAUTH_ENDPOINTS` entry differs from `claude.authorizeUrl` and must be kept. Codex bulk import is serial (priority race). Where: `src/lib/oauth/providers/*`.
- **Loopback callback servers reject cross-origin requests**: legitimate redirects carry no `Origin`; a page doing `fetch(..., {mode:"no-cors"})` to `127.0.0.1` always does, so `isLoopbackOrigin` rejects non-loopback Origins. Zed/Xiaomi callbacks carry no `state`, so try every pending session's private key; strays (probes, prefetch, favicon) are answered without touching sessions or stopping the server; a failed Zed attempt does not stop the proxy (a superseded popup may land after "Try Again"); a reused live listener renews its idle timeout. Where: `src/lib/oauth/utils/server.js`.
- **Secrets stay out of URLs, logs and responses**: `register-session` is a POST (Zed `codeVerifier` is an RSA private key), the Zed proxy logs redacted params, status responses never return the key. Where: `src/app/api/oauth/[provider]/[action]/route.js`.
- **The `/callback` page relays only to expected origins** (opener same-origin or the Codex helper on a fixed loopback port), `postMessage` once per allowed origin, never `"*"`; the modal's `handleMessage` accepts only the dashboard origin or this attempt's callback origin. Where: `src/web/pages/callback/page.js`.
- **The OAuth modal owns its proxy exactly once**: an `openedRef` ledger gates every `stop-proxy`, ownership is taken right after start, all close paths funnel into one idempotent cleanup, parent callbacks live in refs, the open effect depends only on stable primitives (StrictMode reruns must not open tabs). Device-code poll deadline honors upstream `expires_in` (Qoder 300s, default 120s); device flows return `authUrl: null`, never `window.open(null)`. Where: `src/shared/components/OAuthModal.js`.
- **Antigravity advertises the Hub client, `antigravity/hub/2.33.0 darwin/arm64`, from `providers/shared.js` alone.** LiteRouter has no MITM module, so there is no intercepted-client UA rewrite to keep in step; the connection-test probe sends the same identity. The Hermes line rewrites must run before the generic Hermes identity rule, and the official identity block is prepended only when the system text does not already contain "You are Antigravity". Where: `open-sse/providers/shared.js`, `open-sse/config/appConstants.js`, `open-sse/executors/antigravity.js`.
- **Every Kiro / Amazon Q call, token refresh included, builds its identity from `buildKiroIdentityHeaders`**; the machine id is a PBKDF2-SHA256 digest (fixed salt, cached per seed) of the most stable account field, never a raw credential. The `/v1/responses` CreateResponse lane is a fallback for 429 `USER_REQUEST_RATE_EXCEEDED` only (`LITEROUTER_KIRO_CREATE_RESPONSE=auto|always|off`), and only a region in `KIRO_RUNTIME_REGIONS` may reach the hostname that receives the bearer. Where: `open-sse/shared/kiroIdentity.js`, `open-sse/executors/kiro.js`, `open-sse/utils/kiroCreateResponse.js`.
- **OpenDesign Go quota reads a separate `vela_ctrl_` control key from `providerSpecificData.opendesignControlKey`** (the `sk-amr` runtime key cannot see quota) and refuses to guess between workspaces; provider API responses strip that key through `toProviderConnectionResponse`. Where: `open-sse/services/usage/opendesign.js`, `src/lib/providerConnectionResponse.js`.
- **Cloudflare System One**: the body `model` is the short registry `upstreamModelId` (`clef`, `clairic`, ...) while `/ai/run/{model}` keeps the full `@cf/...` id; a `systemOneTransport.responseWrapper` body is unwrapped only when the inner object has `answers` and the outer has none; Clairic (`payloadShape: "fields"`) validates `fields`, other registered models `questions`, unregistered custom nodes either. Where: `src/sse/handlers/systemOne.js`.
- **The Kiro CreateResponse lane is a fallback, not a peer**: in `always` mode a non-ok `/v1/responses` answer falls through to generateAssistantResponse (and is not retried there a second time); parallel `function_call` items keep their own tool index (keyed by `output_index`/`item_id`); its usage carries no cache fields, so cache reads on that lane bill as plain input. Where: `open-sse/executors/kiro.js`, `open-sse/utils/kiroCreateResponse.js`.
- **The OpenDesign Control Key is write-only**: the add-key modal sends it (and an optional workspace id) in `providerSpecificData`, and no provider API response returns it. Where: `src/web/pages/dashboard/providers/[id]/AddApiKeyModal.js`.
