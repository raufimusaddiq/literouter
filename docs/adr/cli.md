# CLI launcher (`cli/`)

- **Only kill a server we own.** The pidfile records pid and port; a pid is ours only if it is the process listening on the recorded port (pids recycle after reboot, so a stale record is dropped). A hide-to-tray child gets its predecessor's pid via the environment to reclaim the port. Never force-kill a foreign listener. `netstat -ano` parsing counts only LISTENING rows and matches the port exactly (2012 must not match 20128). Where: `cli/src/cli/utils/serverProc.js`.
- **Stopping**: the pidfile has `launcherPid`; the launcher must die before its server or it respawns it. Ownership is proven by the server's parent pid (command-line match is a fallback, the bin may be a symlink). On Windows kill the launcher without `/T` (it would take the detached server too); find the tray helper by its `tray.ps1` command line. A pidfile with `launcherPid` skips the legacy takeover check. If an old Node launcher respawns the server, exit 1 with guidance instead of moving to another port. Pidfile dir is `DATA_DIR`, else `~/.9router` (`%APPDATA%\9router` on Windows). Where: `cli/src`.
- **CLI API calls authenticate with a file-based shared secret**: the raw machine ID written by the server plus a random 0600 secret, sent as `x-9r-cli-token`; this lets it reset `authMode` to "password" when OIDC is misconfigured. Subcommands run against a running gateway and skip the launcher flow. Where: `cli/src/cli/api/client.js`.
- **No `postinstall`** (`bun add -g` blocks lifecycle scripts): `ensureRuntime` installs `systray2@2.1.4` lazily, macOS and Linux only, just before `claimPort` so `--help` and `stop` never spawn `bun add`. Server child: cwd `cli/app`, `--dns-result-order=ipv4first`, `NODE_ENV=production`. `cli/bun.lock` is committed (`--frozen-lockfile`). Where: `cli/src`, `cli/hooks`.
- **Update checking is off** unless `NINEROUTER_UPDATE_PACKAGE` names the package (the upstream `9router` is a different product). Where: `cli/cli.js`.
- **Tray**: Windows uses a PowerShell `NotifyIcon` (no unsigned Go binary; Kaspersky flagged `tray_windows.exe`); macOS/Linux use `systray2` (the old `systray@1.0.5` ships a 2017 x86_64 Mach-O that modern dyld rejects, silently) with a best-effort `chmod +x` on install and every tray init (tarball loses the exec bit, EACCES). A detached process has no TTY, so auto-relaunch falls back to tray-only; ignore SIGHUP so closing a macOS terminal keeps the tray; on macOS the current process stays alive (a detached child sits outside the login session and NSStatusItem silently fails). Where: `cli/hooks/trayRuntime.js`, `cli/src/cli/tray/tray.js`.
- **macOS tray details**: the full-color RGBA `icon.png` must not be a template icon (solid white square); killing the tray awaits the Go binary exit (the NSStatusItem must be released before respawn); exit gracefully with `{type:"exit"}` over IPC (SIGKILL leaves a ghost icon). Where: `tray.js`.
- **Autostart**: macOS launchd plist invokes node-free `cli.js` by absolute path with explicit `EnvironmentVariables.PATH` (no `zsh -l -c`); `launchctl unload/load` SIGTERMs the running process, so skip launchctl when the current process is the agent's own instance; `isAutoStartEnabled` requires plist and registration. Windows runs the entry directly with a hidden window (no `9router.cmd` lookup); Linux Desktop Entry `Exec` double-quotes every path. Args of a detached tray child are shared by hide-to-tray respawn and autostart so host and port survive. Where: `cli/src/cli/tray/autostart.js`.
- **TUI keeps stdin raw for the whole session** (toggling adds latency on macOS; keypress plus raw `data` fallback stops arrow escapes leaking). Where: `cli/src/cli/utils/input.js`.
- **Tool configs are written by the local CLI, never by the server.** `literouter setup <tool>` runs on the user's machine, so the config lands in that user's home even when the server is remote, and the minimal profile keeps no server routes or dashboard pages that write tool files (the upstream CLI Tools surface was removed). It talks to the server only through the API-key-authenticated `/v1/models`. Writes are merge-only (just the `literouter` entry changes, every other key survives), atomic (temp file plus rename), mode 0600 because the file holds the key, with a timestamped `.bak-YYYYMMDD-HHMMSS` of the previous file; an unparseable file aborts with nothing changed, an unchanged result writes nothing, `--dry-run` prints with the key masked, and the full key is never printed. One module per tool over shared helpers. Where: `cli/src/cli/commands/setup.js`, `cli/src/cli/setup/`.
- **Pi format** (`~/.pi/agent/models.json`, `$PI_CODING_AGENT_DIR/models.json`, or a legacy `~/.pi/models.json` when only that exists): `providers.literouter = { baseUrl: <server>/v1, apiKey, api: "openai-completions", models }`. Each model gets `input` `["text","image"]` only for vision, `reasoning`, `contextWindow`/`maxTokens` from `context_length`/`max_completion_tokens` (defaults 200000/64000 when missing or out of range), and a `thinkingLevelMap` over Pi's levels `off..max` (`off` maps to `none`, unsupported levels to `null`). Thinking off writes `{}`, never `null` (a null map invalidates the whole file and Pi then drops every provider). A server level Pi cannot express (`thinking`, `ultra`) leaves the map unset so a hand-written one survives. A hand-set model `name` and unknown provider/model keys are kept. Where: `cli/src/cli/setup/pi.js`.
- **Claude Code format** (`~/.claude/settings.json`, or `$CLAUDE_CONFIG_DIR/settings.json`): only the `env` block changes: `ANTHROPIC_BASE_URL` is the server root without `/v1` (Claude Code appends `/v1/messages`; upstream wrote `<origin>/v1` and relied on the `/v1/v1/*` alias routes), `ANTHROPIC_AUTH_TOKEN` is the key, and `ANTHROPIC_DEFAULT_{FABLE,OPUS,SONNET,HAIKU}_MODEL` are set only for the tiers given; tiers not given keep their current values. Where: `cli/src/cli/setup/claudeCode.js`.
- **Codex format** (`~/.codex/config.toml`, or `$CODEX_HOME/config.toml`): `[model_providers.literouter]` with `base_url = <server>/v1`, `wire_api = "responses"` and the key in `http_headers.Authorization` (Codex ignores `auth.json` for custom providers, as upstream found), plus `[profiles.literouter]` (`model`, `model_provider`); root `model`/`model_provider` are left alone and `--default` sets only root `profile`. There is no TOML writer in Bun, so the edit is textual: drop the `model_providers.literouter*` and `profiles.literouter*` tables, append ours, then re-parse with `Bun.TOML.parse` and refuse to write unless our values parse back and every other key parses identical to before (catches inline-table or multi-line-string forms the line edit cannot handle). Where: `cli/src/cli/setup/codex.js`.
- **OpenCode format** (`$OPENCODE_CONFIG`, else `${XDG_CONFIG_HOME:-~/.config}/opencode/opencode.json`, or `opencode.jsonc` when only that exists; trailing commas are tolerated, comments make it abort): `provider.literouter = { npm: "@ai-sdk/openai-compatible", name, options: { baseURL: <server>/v1, apiKey }, models }`, each model with `limit { context, output }` (only when both are known), `modalities` (image input only for vision) and `variants` `{ <level>: { reasoningEffort: <level> } }` from `thinking_levels`; an existing entry's `variants`, `modalities`, `name` and unknown keys are kept (only `limit` is refreshed). Root `model` that is not a string counts as unset. It is set to `literouter/<first>` only when unset, pointing at a literouter model no longer selected, or with `--default`. Where: `cli/src/cli/setup/opencode.js`.
